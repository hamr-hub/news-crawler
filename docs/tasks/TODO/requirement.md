# 新闻爬虫项目需求

## 业务目标

**目标用户**：需要聚合新闻的用户

**要解决的问题**：
1. 新闻来源分散，需要手动收集
2. 无法及时获取最新新闻
3. 重复内容过多
4. 爬虫报错需要人工介入修复

**成功指标**：
- 自动发现并归类新闻网站
- 持续爬取最新新闻并去重
- AI 自动修复爬虫错误
- GitHub 发布后自动处理 Issue

## 范围

### 做
- 通过 Google/Baidu/Yandex 等搜索引擎搜索新闻网站
- 对新闻网站自动归类（国家、新闻类型）
- 循环爬取各新闻网站最新内容
- 相同内容新闻汇总去重
- 爬取出错时 AI 校对并修复
- 发布到 GitHub 并自动处理 Issue

### 不做
- 爬取需要登录的付费新闻
- 存储原始网页内容（只存结构化数据）

## 关键交互

1. **入口**：搜索引擎查询新闻网站
2. **主路径**：搜索 → 发现网站 → 归类标注 → 添加到爬取队列
3. **关键状态**：
   - 待爬取网站队列
   - 爬取中
   - 爬取完成
   - 需要修复

## 数据与接口

**存储方式**：JSON 文件

**字段定义**：
| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 新闻唯一标识 |
| title | string | 新闻标题 |
| content | string | 新闻内容 |
| source | string | 新闻来源网站 |
| country | string | 来源国家 |
| category | string | 新闻分类 |
| published_at | datetime | 发布时间 |
| crawled_at | datetime | 爬取时间 |

## 验收标准

1. **AC1** - 能够通过搜索引擎发现主流新闻网站  
   验证：运行搜索脚本，输出至少 50 个新闻网站

2. **AC2** - 新闻网站按国家和类型归类  
   验证：输出包含 country 和 category 字段的站点列表

3. **AC3** - 循环爬取新闻内容  
   验证：定期执行爬虫，输出 JSON 格式新闻数据

4. **AC4** - 相同内容新闻去重汇总  
   验证：同一新闻多来源只保留一条

5. **AC5** - AI 自动修复爬取错误  
   验证：模拟爬取错误，AI 识别并修复爬虫代码

6. **AC6** - GitHub Issue 自动修复  
   验证：创建测试 Issue，系统自动识别并修复

7. **AC7** - 数据以 JSON 格式保存  
   验证：检查输出目录存在 JSON 文件

## 建议补充

- 考虑添加爬取速率限制以避免被封禁
- 建议添加日志持久化以便问题排查
- 建议添加监控指标（爬取成功率、错误率等）
- 搜索引擎访问受限时的兜底策略
